# Portable math profile v1 — design and admission policy

Status: implementation design, not an admitted runtime. The user explicitly authorized developing a versioned CPU-native portable math profile against the validated original SLEEF reference, with Cura disagreements retained. The separate approved SVF/UMEP release exceptions do not waive this profile's numerical gates. This document and `reports/characterization/p8_portable_profile_v1/policy.json` predeclare the implementation contract and admission gates before production integration.

## Reference amendment and scope

Profile ID: `solweig-portable-sleef-5a1d179d-v1`.

The canonical differential reference is unchanged SOLWEIG-GPU commit `0d7fe742abeeddd890dd58fc76ed7f78bd47faec` running in the retained macOS ARM64 original-CPU environment: Torch 2.14.0 (source commit `08187d9e0fba026dc8217405802ab5381dc88d90`), NumPy 2.4.6, macOS 26.6.2. SLEEF source is pinned to `5a1d179df9cf652951b59010a2d2075372d67f68`. The environment, source, fixture and oracle files are bound by hashes in the policy manifest. A reference is an actual original-upstream execution, not output from the adapted candidate helper. Reference expansion must run that original environment; missing large-scene reference captures are `not_run`, never replaced with candidate-generated goldens or Linux MKL output.

This is an explicit authorized reference-profile amendment. It does not relabel the original Cura/MKL backend as wrong or passed, claim universal upstream CPU parity, or change old reports. Keep Cura original CPU, original/patched CUDA and amended SLEEF reference results in separate result columns. The established original-Cura dense1024 TMRT failure and every measured mask difference remain deviations. New candidate-to-Cura comparisons are mandatory disagreement reports, but are not substituted for the amended-profile admission gate. No new claim of physical accuracy follows from this amendment.

Linux x86-64 and macOS ARM64 are both required targets. A passing M1-only implementation cannot satisfy this profile. Preserve all model quantities, accepted public workflow arguments, TIFF contracts, logical tiles, chronology, 153-patch default physics and all requested outputs. No Torch, CUDA, MKL or network dependency is permitted in the installed own-met runtime.

## Operation specification and residual coefficient limitation

Use the retained isolated M1 snapshot as the starting implementation, not as an already admitted product. Its 750 source tests, nine installed-wheel cases and 18 ten-field/24-band artifact comparisons are prior evidence only.

Preserve float32 SVF square root, SLEEF u10 float32 acos, classifier tan and atan operation sequences, casts and source-defined FMA. Use round-to-nearest ties-to-even, gradual underflow, `fastmath=False`, and no implicit reassociation. Explicit FMA must remain single-rounding; inspect lowered code and test on both ISAs. Correctly rounded float32 sqrt must match the canonical original capture, including special cases. Preserve signed zeros where they affect behavior and separately compare finite/NaN/infinity masks. Do not promise identical NaN payloads when the reference contract only requires masks.

Actual classifier calls are once per scalar patch. Float32 patch tensor-origin scalars combined with float64 solar zero-dimensional values produce float64 coefficient arithmetic; the scalar coefficient is wrapped/cast to float32 when added to the raster. Preserve multiply/add grouping, strict `<`/`>` predicates and equality belonging to neither class. Do not use the invalid historical vectorized Torch classifier oracle.

**Explicitly bounded coefficient policy:** v1 provisionally retains NumPy float64 cos/tan for the solar coefficient path, as the successful M1 snapshot did. It does not claim bitwise equivalence for those primitives or all real-valued inputs. Different intermediate bits are reportable and acceptable only when the exact categorical and unchanged component/final field gates below pass on the predeclared reference matrix on both platforms. Hash-bind the NumPy/compiler/runtime versions; scalar coefficient bits, their float32 wrapped values and first divergent downstream operations must be retained. This is a finite validated-domain contract, not proof for all angles. No epsilon or boundary adjustment is allowed. If either platform fails a categorical or field gate, this implementation cannot be admitted: derive the actual canonical original float64 dispatch from source and validate a source-derived operation port, or revise the proposed implementation under the same gates. Do not silently select the local backend with the easiest oracle.

The snapshot's tan guard `abs(x)<125` is valid for physical ASVF input [0,pi/2], but is not permission to reject previously accepted low-level inputs. Before implementation freeze, audit accepted scalar/array dtypes and domains of all affected entry points. Nonfinite/invalid-SVF behavior must match original semantics. Any reachable finite input outside the adapted helper domain requires the pinned source's complete reduction path or a demonstrably equivalent preserved path with a distinct recorded identity. No new clipping, ValueError, or undeclared NumPy fallback may escape this audit. Implementing a new accepted-input policy would require further approval.

## Selection, public API and identity

During development the profile is selected explicitly only inside an isolated snapshot. After independent admission on both required platforms, use this constant profile as the default in the new candidate version. Preserve existing Python signatures, defaults and legacy CLI flags; do not add a public backend selector merely for this experiment. No environment-controlled or ISA-controlled switch may silently choose MKL, legacy NumPy or a different reference policy. The normal and opt-in compatibility namespaces use the same profile and report it in diagnostics/provenance. Do not alter legacy TIFF schemas solely to add this metadata; use the existing run manifest or a separately versioned provenance sidecar.

Distinguish semantic profile ID from implementation fingerprint. Fingerprint source helper bytes, pinned SLEEF source/configuration, coefficient policy, NumPy/Numba/LLVM/runtime versions, target ISA and relevant floating-point settings. All native caches/checkpoints affected by ASVF or classification must include the profile ID and fingerprint. Simulation/restart identity always includes them; geometry caches containing ASVF or any derived classifier quantity must invalidate on mismatch. Reusing raw-only geometry is allowed only if its manifest explicitly distinguishes that layer and all derived values are recomputed. The first implementation should conservatively invalidate the existing whole geometry generation rather than infer safe partial reuse.

Checkpoint mismatch is a clear rejection; never resume incompatible carried state. Native geometry mismatch triggers a fresh atomic generation with normal corruption/concurrency safeguards. Old manifests without profile identity are stale, not implicitly v1. Imported legacy caches retain their existing explicit trust policy and cannot import precomputed angular state as verified v1. Distinct serial/parallel persistent-JIT identities and the existing cache collision regression must survive. Profile-specific output directories prevent old and new validation artifacts from overwriting one another.

## Predeclared numerical admission

1. Verify reference and source hashes before any comparison. Run canonical primitive captures (411,685 M1 inputs and the retained 189,220 Cura SVF corpus evaluated by original SLEEF upstream). Report sqrt/acos/tan/atan bit metrics, nonfinite/signed-zero behavior and first divergence; primitive bit differences alone are not automatic rejection when the observable contract is satisfied.
2. Require exact actual-call sun/shade masks against original SLEEF for all 24 frozen solar timesteps, all 153 patches, 774 boundary values, all 249 existing M1 frozen SVF values, and all valid unique SVF values from the dense/vegetation admissions. Include already-retained boundary neighbors and specials. Capture new original SLEEF oracles before candidate results are inspected; freeze their input manifest. Do not use the old Cura vector masks. Require exact shape, categorical, missing-value and infinity masks.
3. Run serial and prepared/compiled paths, float32 and supported promoted input cases, contiguous and stride-2 layouts, blocks 17/128/1023, thread counts 1 and 4 on both hosts plus the declared production CPU budget. Exercise lengths 1/7/153/1024/4096, empty/tail paths where accepted, and chunk offsets 0/1/3/7/15. Require identical categories and existing field budgets across variants. Existing known scientific exceptions stay separately labeled.
4. Compare all radiation components and every chronological state field using unchanged `comparison_v1` field rules as adopted by the existing differential harnesses; radiation atol 0.05 W/m²/rtol 1e-5, TMRT 0.01 degrees, UTCI/WBGT 0.02 degrees. Keep all per-field stricter rules, metadata, masks, NoData and timestamps. No RMSE-only acceptance.
5. Execute genuine small own-met workflows (all nine existing installed cases and source variants), then full dense1024 and vegetation1024 cases with all ten fields, 24 bands, 153 patches, unchanged forcing and logical extents. Compare Linux and M1 candidates with canonical original-SLEEF outputs and retain direct Linux/M1 comparisons using the same gates. Use the same logical scene, not an easier substituted M1 scene. Missing reference/hardware/resource completion blocks the affected gate. Process-tree cap is 12 GiB with 20 ms sampling; failures and partial artifacts retained.
6. Build retained wheels and install into fresh environments on both platforms. Verify origin outside source tree, no Torch/CUDA/MKL/acquisition imports, no network during own-met execution, source/wheel helper-byte identity and included Boost license. Run genuine chronological tests, profile/cache/checkpoint migration/rejection tests, corrupted/concurrent cache handling and serial/parallel collision regression. Revalidate public workflow signatures/CLI contracts. Required tests cannot be skipped to admit the profile.

Every comparison records reference category, original/source hashes, fixture hashes, full invocation, environment, thread/affinity, cache/JIT state, raw outputs, errors and worst coordinates/timestep. A difference accepted by an existing budget is still reported. The Linux original-Cura disagreement report remains visible even if every amended-profile gate passes.

## Performance and implementation handoff

Changing the math profile invalidates transfer of old end-to-end speed claims. Historical P7 evidence remains historical. Freeze a new candidate source/protocol and first-use/geometry-cold/geometry-warm conditions only after numerical admission; preserve equal work, 12 GiB process-tree accounting and required import/JIT/geometry/output timing. Measure original SLEEF CPU and candidate on matched hardware where executable. On Cura, original MKL CPU remains a separately labeled different-profile comparison with numerical deviations; do not publish it as equal-output speedup. Reset acceptance baselines rather than attaching new-profile timings to an old source inventory. No benchmarking during competing numerical jobs.

Worker sequence: (a) audit helper domains and reference bindings; (b) implement in isolated snapshot, explicit identity plumbing and regression tests; (c) secure missing original-SLEEF captures without candidate contamination; (d) execute staged local/M1 and owned-root Cura admission; (e) retain wheels/raw artifacts; (f) independent review before main integration and a new performance freeze. Cura's old owned root has been removed: any remote work uses a newly authorized ledger-owned root through its owner, with hash-verified download and cleanup.

Independent reviewer must check actual scalar promotion/dispatch, license attribution, complete accepted domains, lowered FMA/rounding behavior, no hidden fallback, cache/checkpoint invalidation, retained original-Cura failures, and actual executable source/wheel evidence. Prior prototype counts are not new-profile passes. Failure requires fixing implementation or reporting a policy-level conflict; it cannot be resolved by changing this gate after seeing the result. Approval to develop the profile is not release approval.
